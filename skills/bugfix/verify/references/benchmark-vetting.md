# 数字体检七问

前后对比的数字是最容易错得心安理得的证据：热缓存、单侧 debug 构建、工作根本没在计时区间里，每个都能造出一次"可信的加速"。报告数字或据此行动之前，逐问要运行证据：

1. **limiter 是什么？** 为什么不是两倍快/慢——受限在哪个资源上。
2. **两侧同调优了吗？** 都按生产形态跑：同构建类型、同开关、同预热。
3. **破物理上限了吗？** 带宽、核数、访存的理论上限对得上吗。
4. **有没有出错？** 错误、降级、静默走错路径，都会伪装成加速。
5. **交替跑过吗？** A/B/A/B 多轮，报中位数和区间，不报单次。
6. **端到端相关吗？** 用户等待的路径上，这个数字占多少。
7. **工作真在计时区间里吗？** 计时区间内确实执行了被改的工作。

**结论四选一**：更快 / 更慢 / 无可测差异 / 不可下结论。说不出 limiter、或有一侧没按生产形态跑，就只能写"不可下结论"。
