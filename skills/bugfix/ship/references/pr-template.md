# PR 描述模板

复制为 PR body；字段不适用的写 N/A 而不是删字段：评审者靠固定字段索引信息。

## Why

<症状句：执行 X 后，Y 应为 A，实测为 B。+ 问题标识：issue 链接 / 报告人>

<逻辑或流程改动：附最小视觉——伪代码、调用树或浅文件树>

## 根因

<被证实的假设：一段话机制，症状如何从根因长出来>

## 修复

<改了什么；为什么这是最小正当改动；为什么在根因处修>

## 证据

- **Before**：<基线上的真实输出 / 失败测试运行，redacted>
- **After**：<修复版上的真实输出 / 通过的测试>

<回归测试结果；影响面结论：逐项确定性等级（口说 / 指到行 / 推演排除 / 代码证明 / 真实复现）与去留>

## 门

**类型**：one-way | two-way

<一句话影响面：这个改动碰不到什么，凭什么>
