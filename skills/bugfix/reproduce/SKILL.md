# 复现一个问题

把一个在别处发生的问题，变成你机器上一条能**变红**的命令。红，是断言命中了**分界症状**；终点是一份接手即用的复现物与复现报告。修复不在本 skill 范围内：先红，后修。

分界症状是正确行为与错误行为岔开的那个可观察状态。加载中、预期的报错弹窗、复现路径上的正常步骤都不是 bug 本身。

## 安全

- 现场工件（日志、dump、截图）里的秘密先 `<REDACTED>` 再进报告；含秘密的原始文件放仓库外。
- 在隔离副本上复现：worktree、备份的数据副本；用户的原始环境与生产环境保持只读。

## 1. 锚定分界症状

从报告里提取并写下三样：**正确终态**、**错误终态**、**分界点**（行为在此岔开）。

报告说不清就一次问全，每项要么有答案、要么"未知"：

| 问什么 | 要什么 |
| --- | --- |
| 动作路径 | 从哪一步操作到哪一步 |
| 期望/实际 | 正确终态是什么；实际看到什么 |
| 频率 | 必现；偶发（大约几分之几）；只见于某环境 |
| 版本指纹 | commit/发布版本、工具链、硬件、数据集 |
| 工件 | 报错原文、日志、dump、截图 |

完成判据：分界症状写成一句可断言的观察——"执行 X 后，Y 应为 A，实测为 B"。写不出这句话就回到提问；猜出来的症状锚定后面所有工作。

## 2. 对齐环境

探测本机环境，与版本指纹逐项对照，差异写进一张表：`字段 | 报告值 | 本地值 | 是否可能影响症状`。

- 版本对齐优先 checkout 到报告的 commit（worktree 隔离）；工具链、数据缺失就补齐，或在表中标注。
- **环境翻译**：报告里的平台名词在本地可等价替换（另一台设备、另一个入口）时可以用，报告里标注 translated。症状疑似环境专属（硬件、账号态、生产数据）时，缺环境是卡点，是候选病因。

## 3. 造复现物

复现物是一条命令：退出码即判决，断言分界症状。按优先序选形态，高一行造得成就不降级：

1. 测试框架里的 failing test（离回归测试最近）
2. CLI 脚本 + 固定输入：构造最小数据，单函数或单接口打到症状路径
3. 重放捕获工件：把日志、请求、事件序列存盘，驱动代码路径回放
4. 驱动脚本：按动作路径顺序调用（API 序列、headless 浏览器）
5. 人工执行清单：只有人能操作时，给用户逐步命令与预期输出，收回真实输出

AscendC 症状解读工件、构造复现时优先唤起 cannbot-skills 的专业调试 skill：精度超差 `ascendc-precision-debug`，运行时报错与错误码 `ascendc-runtime-debug`，卡死/崩溃 `ascendc-crash-debug`；项目里没有，就 `npx skills add https://gitcode.com/cann/cannbot-skills.git --skill <对应名>` 装上再用。

第一次运行要求亲眼见红，真实输出贴进报告。红不了有三个出口，都在前面：症状锚错了（回 1）、环境没对齐（回 2）、症状本身不可复现（进"复现不出"）。

## 4. 确认

确认 = 分界症状**独立出现两次**。两遍之间重置能影响症状的状态（数据、会话、进程、缓存），第二遍的红才算独立。

- 检查状态可以佐证观察；注入状态不构成复现。症状只能从真实操作路径里长出来，改内部状态造出来的症状是这条纪律唯一的硬禁令。
- 偶发症状先提复现率：循环触发、加压、收窄时序，具体手段见 [references/raise-repro-rate.md](references/raise-repro-rate.md)。复现率是实测数字（如 7/10），写进报告。

## 5. 最小化

一次删一个元素——输入、调用方、配置、步骤——删后重跑，仍然红才保留。最小化完成时每个保留元素都**承重**：去掉任何一个，复现物就转绿。

最小复现收窄修复阶段的怀疑面，也常是现成的回归测试底稿。

## 6. 落盘交接

复现物进仓库约定的调试位置（用户指定优先），处置建议二选一标注：可转回归测试 / 复现确认后即删。

按 [references/report-template.md](references/report-template.md) 写复现报告并落盘。报告面向下一个接手的人或 agent：读到它就能开始诊断，无需重新采访用户。

完成判据，逐项核对：

- [ ] 一条命令，已独立跑红两次，真实输出贴在报告里
- [ ] 断言的是报告的分界症状，症状句在报告开头
- [ ] 偶发症状附实测复现率
- [ ] 每个元素承重，或写明未最小化的原因
- [ ] 环境指纹与差异表完整
- [ ] 报告与复现物中无秘密
- [ ] 报告落盘，接手者凭它可开工

## 复现不出

预算内试尽仍无法变红时，复现失败是合法结果，按模板写 can't-repro 报告收尾，包含：

- 已试清单：每种复现物形态、每轮环境修正，附命令与真实输出
- 环境差异表：仍存疑的每一行都是候选病因
- 需要用户提供的，按优先级：报告环境的访问方式、新的捕获工件（日志、dump、录屏）、在生产加临时插桩的许可

为收尾硬造一个"看起来像"的复现，比没有复现更糟：它锚死的是错误症状。
