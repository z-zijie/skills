# 复现报告模板

复制到用户指定的位置，或仓库约定的调试目录；命名带上问题标识（issue 号或一行摘要）。两种结局各自取用对应字段，不适用的写 N/A 而不是删字段：接手者靠固定字段索引信息。

## 头部

- 问题标识：issue 链接 / 报告人 / 一行摘要
- 状态：已复现 | 已复现（translated）| 复现不出
- 谁在哪台机器、何时完成

## 分界症状

一句话断言式：执行 X 后，Y 应为 A，实测为 B。

期望终态、实际终态、分界点各一行，注明报告原话还是转述。

## 复现物

- 一条命令：`<完整命令行>`
- 断言方式：退出码 / 输出 diff / 断言失败的报错原文
- 处置建议：可转回归测试（写落点）/ 复现确认后即删
- 最小化：每个承重元素一行——`元素 | 去掉后的表现（转绿）`

## 证据

- 第一次红的完整输出（redacted）
- 独立第二次红的输出，中间的 reset 动作写明
- 偶发症状：复现率 N/M，触发方式

## 环境指纹

`字段 | 报告值 | 本地值 | 差异影响`，至少覆盖：commit、分支、工具链、硬件、数据集、账号态、关键配置。

translated 的翻译逐条列出：报告名词 → 本地等价物 → 为什么不影响症状。

## 给接手者

- 已排除：试过的复现物形态与环境修正（can't-repro 报告里这一节是主体）
- 仍开放的怀疑面：分界点附近的代码区域、环境差异表里的存疑行
- 建议的下一步：从哪里开始诊断；failing test 形态的复现物可直接作为修复阶段的红测试
