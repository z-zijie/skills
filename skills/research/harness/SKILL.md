# 实验基建

实验的可信度在第一轮实验之前就定死了。测量没冻结就开跑，是在噪声里爬坡，keep / discard 全是掷硬币。终点是一套冻结的测量设施：一条命令出指标，噪声底是实测数字，基线已入账。

## 1. 定指标

- **单一主指标**：一个数字，方向明确（越高越好或越低越好）。辅助观测（内存、时长、正确性）记录但不裁决。
- **可比性优先**：固定预算（时间、步数、token 量），使任何改动之间直接可比。预算变了，全部历史结果作废。
- 指标必须由一条命令打印出来；打印不出来的东西管不了。

## 2. 建测量

- 测量脚本化：`run.sh` / `bench.py`，一条命令跑完一个实验并输出固定格式。按 create-tool 的纪律造：单文件、自包含、一行答案；工具随 run 提交，是评审者能重跑的杠杆。
- 主指标独占一行且可 grep（如 `metric: 0.9979`），资源行同理。
- 输出里带**错误计数与工作量计数**：失败往往很快，报错被当成加速是常见事故。
- 随机性固定（种子、数据顺序、预热次数），否则噪声底测不住。
- **上下文卫生**：输出重定向 `> run.log 2>&1`（不用 tee），主上下文只进 grep 出的关键行，崩溃才 tail。

## 3. 证灵敏度，然后冻结

- **对照检验**：挑一个已知该起效的扰动（把某参数调到明显离谱），确认指标会动。指标不动，测的是别的东西，先修测量。
- **噪声底**：同一配置连跑至少 5 次，记中位数与极差。run-to-run 波动就是**噪声底**：delta 不超过它，等于没有可测差异。噪声底写进台账，此后每轮裁决都对着它。
- **冻结**：测量脚本、数据、预算、指标口径从此不许改。必须改时开新版本，台账记断代，旧结果只在新版本内比较。

## 4. 基线与回归门

- **基线**：原样跑第一轮，进台账第一行。没有基线的提升无法自证。
- **回归门**：必须保持绿的检查（既有测试、正确性断言、资源上限）。keep 的前提是指标过线**且**门绿；门红的成绩再好也是坏改动。

完成判据，逐项核对：

- [ ] 一条命令出主指标，格式可 grep
- [ ] 灵敏度有对照实验记录（扰动确实动了指标）
- [ ] 噪声底是实测数字（次数、中位数、极差都在）
- [ ] 基线行与门绿记录已入台账
- [ ] 冻结声明落盘（脚本指纹或版本号）
