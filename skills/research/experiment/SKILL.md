# 实验

一轮实验只回答一件事。一改一测，keep 或完整回退，绝不堆未测改动；多轮之间只有台账与 git，不靠对话记忆。

## 前置

- harness 已冻结。未冻结先走 harness，否则本轮结果作废。
- 本轮假设已预注册进台账（hypothesize 产出）。

## 单轮流程

1. 读台账全表（防重复，找 near-miss）。
2. 改动：只改机制句里的 D，最小 diff。
3. `git commit`：实验即提交，回退靠 reset，不靠手改回去。
4. 跑：固定预算内，`> run.log 2>&1`，不用 tee，不许日志灌进上下文。
5. 取数：只 grep 主指标与资源行。grep 输出为空即崩溃，`tail -n 50 run.log` 看栈。grep 撑不住的抽取（多行、聚合）第三次出现时，按 create-tool 造 extract 工具，别每轮手写。
6. 裁决：
   - delta 超噪声底且门绿 → **keep**，branch 前进；
   - 否则 → **discard**，`git reset` 回本轮起点；
   - 数字反常（超理论极限、错误数非零、接近噪声底）或结果要进报告 / 理论化时，先过 vet 再定。
7. 台账补行（after / delta / status / gate / lesson），一轮一落盘。

## 崩溃政策

- 蠢错（typo、缺 import）：修复，重跑。
- 想法本身不成立：记 crash，走下一轮。
- 修 2-3 次仍崩：放弃本轮，记 crash。
- 超时（预算两倍）：杀掉，按失败处理。

## 并行

多条独立假设同时在场时（autoresearch 的并行档位）：一假设一 worktree / 一分支，互不写同一份状态，裁决各自独立。会碰同一份状态的假设不并行，串行跑。并行轮的胜者先过 vet 的赢家诅咒复跑，确认后才 keep。

完成判据，逐项核对：

- [ ] 预注册的机制句未被改动
- [ ] git 状态与裁决一致（keep = 提交在；discard = 已 reset）
- [ ] 台账一行已补齐
- [ ] 主上下文里只有 grep 出的关键行
