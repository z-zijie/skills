# 复盘

复盘对象是方法，不是感想。教训必须有结构性着落：同一句话写到第二遍，就该变成结构，不是更多文本。终点是每条教训都指着具体改动。

## 1. 挖类别

过台账 lesson 列与走过的弯路，归类：

- 哪类假设总在浪费轮数（预注册时就该筛掉的形状）；
- 哪类崩溃反复出现（该进 harness 的回归门拦住）；
- 哪个环节总靠人提醒（该写进对应 skill）；
- 停止规则准不准（早停了，还是空转了才停）。

## 2. 按层级修（高 → 低）

1. **改 skill 本身**：这条纪律写进对应 SKILL.md，下一次直接走对。
2. **加门**：harness 回归门里加一条检查，自动拦。
3. **加脚本 / lint**：机器拦，不靠记性。脚本按 create-tool 造，落在研究目录，随 run 提交。
4. 最后才是文档。

研究方法本身是被迭代的产品：这次跑通的流程与 skill 描述有出入，改 skill，让描述追上现实。

## 3. 交付

复盘结论落盘（研究目录 `retro.md`，或并入报告的开放问题节），每条教训一行：

```
类别 | 教训 | 着落（改了哪个文件哪一层）
```

完成判据，逐项核对：

- [ ] 每条教训指着具体改动（文件 + 层级）
- [ ] 没有着落的教训已删：留着只会变成沉积层
- [ ] 被改的 skill / 门 / 脚本与其描述一致
