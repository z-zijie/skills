# 假设

假设是机制句，不是愿望。"试试把学习率调大"不是假设；"因为大 batch 下梯度噪声更小，warmup 翻倍应使前 500 步损失下降加快"才是。终点是一个排好序的候选池，入选者预注册进台账。

## 1. 机制句

每条假设写成一句话：

**若机制 M 成立，则改动 D 应使指标 I 变化至少 δ（方向写明）。**

- M 命名具体机制：什么、通过什么途径、影响什么。"优化一下""调调参数"不合格。
- δ 参照噪声底：低于噪声底的预测等于没有预测。
- D 是一个可单独验证的最小改动，一轮实验测完。

## 2. 找来源

按序扫，够一轮用就停：

1. 先验（theorize 落盘的 `model.md`）：模型与它的未测预测最优先，已驳清单防重测
2. 台账里的 near-miss：差一点成立的轮次，组合它们
3. survey 的"可借方法"与"矛盾证据"两栏
4. 代码与系统里读出的嫌疑点（重读 in-scope 文件找新角度）

## 3. 候选池：宽进严出

- **宽进**：每轮为候选池收多条机制句，机制之间要有真实差异（不同 M，不是同一机制的参数变体），类别横跨结构 / 数据 / 参数 / 口径。
- **滚动落盘** `candidates.md`：新候选追加；已预注册的标注台账 id；被驳的标记一句原因；失去意义的删除。
- **严筛**：按信息增益 / 成本排序，先试**便宜且无论成败都排除一大片**的；能用便宜代理先筛的先用代理筛，幸存者再上全预算。
- **严出**：出口不归这里管，生成阶段不自我审查，裁决交给 experiment 与 vet 的硬标准。
- 一改一测，一条假设对应一个改动，不打包。

## 4. 前提攻击

同一前提下的改动连续 2-3 轮失败时，停下来：把前提本身写成一条假设，直接测它，再写下一个默认该前提成立的修复。

## 5. 预注册

入选者（串行轮取榜首，并行轮取前 N 条）在实验运行前，把机制句写进台账 hypothesis 列，一条一行。跑完不许改。

完成判据，逐项核对：

- [ ] 入选者已预注册进台账，M / D / I / δ 四要素齐
- [ ] 候选池机制间有真实差异，且按信息增益 / 成本排好序
- [ ] 每条可单独验证，无打包
- [ ] 已驳机制未被重复提名
