# 调研

每条结论跟到拥有它的源头。终点是一份四栏纪要：别人做到哪了、死在哪了、什么能搬、哪里在打架。长阅读交给后台 agent，主线程只收纪要。

## 1. 划来源

按可信度取用，一手优先：

1. 官方文档、规范、RFC
2. 源码与真实提交历史
3. 论文原文（预印本标注版本）
4. 一方工程博客、issue 讨论
5. 二手转述：最后手段，必须标注"二手"

- 代码注释里引用的论文是现成弹药库，先扫一遍。
- 本项目的 issue、ADR、历史实验记录同样是一手来源。

## 2. 四栏纪要

写入 `survey.md`（研究目录约定位置）：

| 栏 | 收什么 |
| --- | --- |
| 已知结论 | 别人已证明的，每条同句带出处 |
| 他人失败 | 试过不行的，防止重复踩坑；负结果也是结果 |
| 可借方法 | 可直接搬的方法、参数、代码、数据 |
| 矛盾证据 | 互相打架的结论，研究机会往往在这 |

## 3. 纪律

- **绝不编造引用**：链接只给真实读过的；查不到写"未找到"，不硬凑。
- 二手来源必须标注；引用论文给标题与链接，不给凭印象的页码或数字。
- 纪要控制在能一遍读完的长度；长材料留给后台 agent，纪要只收结论与出处。
- 循环中卡住时回来重读：没试过的方向通常在"可借方法"和"矛盾证据"两栏里。

完成判据，逐项核对：

- [ ] 四栏齐全（允许某栏为空，写明查过没有）
- [ ] 每条结论同句带出处，无凭空引用
- [ ] 能一句话回答"这个问题别人做到哪了"
- [ ] 主线程未吞入长原文
